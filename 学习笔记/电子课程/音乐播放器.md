# 基于 STM32 的嵌入式音乐播放器设计

## 一、项目概述

嵌入式音乐播放器是 STM32 开发的经典综合项目，涉及 SD 卡文件系统、音频解码、I2S 音频输出、LCD 显示与触摸交互等多个技术领域。整体架构分为四层：**数据存储层（SD 卡 + FATFS）→ 音频解码层（硬件解码 VS1053/软件解码）→ 音频输出层（I2S + DAC）→ 人机交互层（LCD + Touch）**。

---

## 二、硬件需求

### 2.1 主控芯片 — STM32

| 型号 | 适用场景 | 关键资源 |
|------|----------|----------|
| STM32F103 | 入门级，配合 VS1053 硬件解码 | 72MHz、SPI、I2S（模拟） |
| STM32F407 | 中级，可软件解码 WAV/MP3 | 168MHz、I2S 硬件、DSP 指令 |
| STM32F429 | 高级，带 LCD 控制器 | 180MHz、LTDC、TFT 接口、SDRAM |
| STM32H743 | 旗舰级，FLAC 软解 | 480MHz、双精度 FPU、SAI |

选择依据：音频采样率（44.1kHz/48kHz）决定 CPU 最低负荷；若软解 MP3，主频建议 ≥ 168MHz；若需 LCD 显示，优选带 LTDC 的 F429/H7 系列。

### 2.2 音频解码方案

**方案 A：VS1053/VS1003 硬件解码芯片**

通过 SPI 接口与 STM32 通信，内置 DSP 核，支持 MP3/WMA/OGG/FLAC/WAV 硬解，自动处理音频帧的解码和 PCM 输出。STM32 只需通过 SPI 向 VS1053 发送音频数据流，VS1053 通过 I2S 或 DAC 引脚输出模拟信号。缺点是增加 BOM 成本，但极大降低 CPU 负荷。

**方案 B：软件解码（Helix/Tremor/libmad）**

在 STM32 上运行解码库，直接输出 PCM 数据。Helix 针对 ARM Cortex-M 优化，可实现在 F407 上解码 MP3。Tremor 用于 OGG Vorbis 解码。WAV 格式无需解码库，直接解析文件头后读取 PCM 数据送入 I2S 即可。软解方案节省硬件成本，但对 CPU 主频和 RAM 有较高要求。

**方案 C：音频编解码芯片（WM8978/CS43L22）**

兼具 ADC 和 DAC 功能的音频 Codec，通过 I2S 接收数字音频数据，内部完成 DAC 转换、音量调节、EQ 滤波等。WM8978 还支持麦克风输入和录音功能。

### 2.3 音频输出方式

| 方式 | 音质 | 电路复杂度 | 适用场景 |
|------|------|-----------|----------|
| 片上 DAC | 一般（12bit） | 低 | 简单波形输出 |
| PWM 滤波 | 较差 | 低 | 蜂鸣器/简单音频 |
| **I2S + 外部 DAC** | **优秀** | 中 | **音乐播放器标准方案** |

**I2S（Inter-IC Sound）** 是数字音频设备间传输 PCM 数据的标准总线，包含三条关键信号线：
- **SCK（位时钟 BCLK）**：每位音频数据对应一个脉冲，频率 = 采样率 × 位深 × 声道数
- **WS（左右声道时钟 LRCK）**：指示当前数据属于左声道还是右声道，频率 = 采样率
- **SD（串行数据）**：按位传输 PCM 音频样本

常见的外部 DAC 芯片：
- **PCM5102A**：廉价的 I2S 立体声 DAC，内置 PLL 无需外部 MCLK，信噪比 112dB，适合入门
- **CS43L22**：超低功耗立体声 DAC，支持耳机放大，常用于便携设备
- **MAX98357**：I2S 输入的数字功放，可直接驱动扬声器

### 2.4 SD 卡存储

SD 卡支持两种通信模式：
- **SPI 模式**：使用 SPI1/SPI2，引脚少（CS/SCK/MISO/MOSI），速度较慢，但所有 STM32 均支持
- **SDIO/SDMMC 模式**：4 位并行总线（CMD/CLK/D0-D3），速度可超 20MB/s，显著提高大文件读取速率

建议使用 **SDIO（4位模式）** 以保证高码率音频文件（如 FLAC）的实时读取。SD 卡需格式化为 **FAT32** 文件系统。

### 2.5 LCD 触摸屏

| 屏幕类型 | 接口 | 特点 |
|----------|------|------|
| 3.5寸 TFT ILI9488 | 16位并口 FSMC | 性价比高，适合 F103 |
| 4.3寸 RGB TFT | LTDC + SDRAM | 需要 F429 以上，色彩丰富 |
| OLED 0.96寸 | I2C/SPI | 简单显示，适合 Mini 项目 |

触摸方案：
- **电阻触摸（XPT2046）**：SPI 接口，成本低，支持单点触摸
- **电容触摸（FT5x06/GT911）**：I2C 接口，多点触控，体验好

**管脚分配示例（LCD + Touch）**：

| 功能 | STM32 管脚 |
|------|-----------|
| LCD_CS | PG6 |
| LCD_RS/DC | PG12 |
| LCD_WR | PG7 |
| LCD_RD | PG8 |
| LCD_RST | PG11 |
| LCD_DB0~DB15 | PD0~PD15 |
| TOUCH_CS | PB1 |
| TOUCH_IRQ | PB0 |

> 注：以上仅为示例，实际管脚分配请参考 `LCD.h` 和 `TOUCH.h` 中的定义。

## 三、文件系统（FATFS）

### 3.1 FATFS 简介

FatFs 是面向嵌入式系统的 FAT 文件系统模块，完全由 ANSI C 编写，支持 FAT12/FAT16/FAT32 和 exFAT。STM32CubeMX 已集成 FatFs，可在配置界面中直接启用。

### 3.2 移植与接口

FatFs 与底层硬件之间的接口在 `diskio.c` 中实现，关键函数：

```c
DSTATUS disk_initialize(BYTE pdrv);   // 初始化 SD 卡
DSTATUS disk_status(BYTE pdrv);       // 获取设备状态
DRESULT disk_read(BYTE pdrv, BYTE *buff, LBA_t sector, UINT count);
DRESULT disk_write(BYTE pdrv, const BYTE *buff, LBA_t sector, UINT count);
DRESULT disk_ioctl(BYTE pdrv, BYTE cmd, void *buff);  // 控制命令（GET_SECTOR_SIZE 等）
```

### 3.3 文件操作流程

音乐播放器中的典型操作：

```c
FATFS fs;                          // 文件系统对象
FIL file;                          // 文件对象
FRESULT res;

f_mount(&fs, "", 1);               // 挂载文件系统
f_open(&file, "music.wav", FA_READ); // 打开音频文件

// 循环读取数据到缓冲区送入解码器
while (bytes_read > 0) {
    f_read(&file, buffer, BUF_SIZE, &bytes_read);
    send_to_decoder(buffer, bytes_read);
}

f_close(&file);                     // 播放完毕关闭文件
f_mount(NULL, "", 0);              // 卸载文件系统
```

### 3.4 中文长文件名支持

在 `ffconf.h` 中配置：
```c
#define FF_USE_LFN      2          // 使用长文件名（堆分配）
#define FF_MAX_LFN      255        // 最大文件名长度
#define FF_CODE_PAGE    936        // 简体中文代码页
```

需要添加 `cc936.c` 文件以支持中文编码转换。

## 四、音频数据处理流程

### 4.1 WAV 文件格式

WAV 作为无压缩格式在嵌入式中最易处理，其结构为：

```
RIFF Header (12 bytes)
  ├── ChunkID: "RIFF" (4B)
  ├── ChunkSize: 文件总大小-8 (4B)
  └── Format: "WAVE" (4B)

fmt Subchunk (24 bytes)
  ├── Subchunk1ID: "fmt " (4B)
  ├── Subchunk1Size: 16 (PCM) (4B)
  ├── AudioFormat: 1=PCM (2B)
  ├── NumChannels: 1/2 (2B)
  ├── SampleRate: 44100 (4B)
  ├── ByteRate: SampleRate*Channels*BitsPerSample/8 (4B)
  ├── BlockAlign: Channels*BitsPerSample/8 (2B)
  └── BitsPerSample: 16 (2B)

data Subchunk
  ├── Subchunk2ID: "data" (4B)
  └── Subchunk2Size: 数据大小 (4B)
  └── Audio Data (PCM samples)
```

解析时读取 Header 获取采样率、位深、声道数，据此配置 I2S 参数，然后循环读取 data 段 PCM 数据送入 I2S DMA 传输。

### 4.2 MP3 解码（Helix 库）

Helix MP3 解码器针对 ARM 平台优化，解码流程：
1. 读取 MP3 文件中的同步帧（每个帧包含 1152 个采样）
2. 调用 `MP3DecDecode()` 解码一个帧
3. 将解码后的 PCM 数据送入 I2S 发送缓冲
4. 通过 DMA 半传输/完成中断实现双缓冲（ping-pong buffer）

### 4.3 双缓冲（Ping-Pong Buffer）机制

为避免音频播放卡顿，使用两个缓冲区交替工作：

```c
#define BUFFER_HALF_SIZE  512
int16_t audio_buffer[BUFFER_HALF_SIZE * 2];
int16_t *active_buffer;

// DMA 半传输中断——填充前半段
void HAL_I2S_TxHalfCpltCallback(I2S_HandleTypeDef *hi2s) {
    active_buffer = &audio_buffer[0];
    need_fill = 1;
}

// DMA 传输完成中断——填充后半段
void HAL_I2S_TxCpltCallback(I2S_HandleTypeDef *hi2s) {
    active_buffer = &audio_buffer[BUFFER_HALF_SIZE];
    need_fill = 1;
}

// 主循环中填充
while (1) {
    if (need_fill) {
        f_read(&file, active_buffer, BUFFER_HALF_SIZE * 2, &bytes_read);
        need_fill = 0;
    }
}
```

## 五、I2S 音频输出配置

### 5.1 STM32CubeMX 配置

1. 选择 I2S 外设（如 I2S3），设置模式为**全双工主机**或**传输主机**
2. 配置参数：
   - **Standard**：Philips 标准（MSB 对齐）
   - **Data Format**：16 位或 24 位
   - **Audio Frequency**：根据文件采样率设定（44100/48000/96000）
   - **Clock Source**：外部 PLLI2S 或内部时钟
3. 使能 I2S 的 DMA 请求，选择 SPI 的 TX 通道，方向为内存到外设
4. 配置 GPIO：I2S_CK、I2S_SD、I2S_WS 对应管脚

### 5.2 动态切换采样率

不同文件的采样率可能不同，播放前需重新初始化 I2S：

```c
void I2S_SetSampleRate(uint32_t sample_rate) {
    HAL_I2S_DMAStop(&hi2s3);
    HAL_I2S_DeInit(&hi2s3);

    hi2s3.Init.AudioFreq = sample_rate;
    HAL_I2S_Init(&hi2s3);
    HAL_I2S_Transmit_DMA(&hi2s3, (uint16_t*)audio_buffer, BUFFER_SIZE);
}
```

### 5.3 音量控制

在将 PCM 数据送入 DMA 缓冲区前，乘以音量系数实现软件音量控制：

```c
void apply_volume(int16_t *buffer, uint16_t size, float volume) {
    for (int i = 0; i < size; i++) {
        int32_t sample = buffer[i] * volume;
        // 限幅防削波
        buffer[i] = (int16_t)(sample > 32767 ? 32767 :
                     sample < -32768 ? -32768 : sample);
    }
}
```

### 6.2 触摸事件处理

```c
typedef struct {
    uint16_t x, y;
    uint8_t pressed;
} TouchPoint;

TouchPoint touch_scan(void) {
    TouchPoint tp = {0};
    if (TP_IRQ_Pin == 0) {          // 检测触摸中断
        SPI_ReadReg(TP_CMD_READ_X); // 读取 X 坐标
        SPI_ReadReg(TP_CMD_READ_Y); // 读取 Y 坐标
        tp.pressed = 1;
    }
    return tp;
}

void process_touch(TouchPoint tp) {
    if (!tp.pressed) return;
    if (tp.x >= PLAY_BTN_X && tp.x <= PLAY_BTN_X + BTN_W &&
        tp.y >= PLAY_BTN_Y && tp.y <= PLAY_BTN_Y + BTN_H) {
        toggle_play_pause();
    }
    // 处理进度条拖动、音量调节等...
}
```

## 八、常见问题与优化

### 8.1 音频卡顿/断流
- 原因：SD 卡读取速度跟不上播放速率
- 解决：使用 SDIO 4 位模式替代 SPI；增大 DMA 缓冲区；启用 DMA 双缓冲

### 8.2 I2S 无声音
- 检查 MCLK 是否使能（部分 DAC 需要外部主时钟）
- 确认 I2S 管脚复用功能配置正确
- 检查 DAC 芯片的供电和复位引脚

### 8.3 触摸不准
- 执行触摸校准，将 ADC 原始值映射到屏幕坐标
- 校准算法：两点校准或三点校准

### 8.4 中文文件名乱码
- FATFS 配置 `FF_CODE_PAGE` 为 936
- 添加 `cc936.c` 文件，启用长文件名支持

## 九、总结

基于 STM32 的嵌入式音乐播放器覆盖了嵌入式开发的多个核心领域：文件系统移植（FATFS）、外设驱动（SDIO/SPI/I2S/LCD/Touch）、数据处理（音频解码）、DMA 传输与中断管理。项目可根据需求选择 VS1053 硬件解码（快速实现）或 Helix/libmad 软件解码（降低成本），配合 I2S 外部 DAC 获得高保真音质。LCD 触摸屏提供了友好的人机交互界面，是综合运用 STM32 外设资源的理想实战项目。
