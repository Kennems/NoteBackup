# 计算机组成原理

## 一、计算机系统概述

### 1.1 计算机的发展历程

- **第一代（1946–1957）**：电子管计算机，如 ENIAC（1946），使用机器语言编程
- **第二代（1958–1964）**：晶体管计算机，使用汇编语言，出现高级语言（FORTRAN、COBOL）
- **第三代（1965–1971）**：中小规模集成电路，操作系统出现
- **第四代（1972–今）**：大规模/超大规模集成电路，微处理器诞生（Intel 4004, 1971）

### 1.2 冯·诺依曼体系结构（von Neumann Architecture）

核心思想：**存储程序**（Stored-Program Concept）—— 指令和数据以同等地位存放在存储器中，按地址访问。

**五大部件**：

| 部件 | 功能 |
|------|------|
| 运算器（ALU） | 算术运算和逻辑运算 |
| 控制器（Control Unit） | 取指令、译码、控制执行 |
| 存储器（Memory） | 存放指令和数据 |
| 输入设备（Input） | 将外部信息转换为计算机内部信号 |
| 输出设备（Output） | 将处理结果转换为外部可识别的形式 |

**工作过程**：
1. 控制器从存储器取指令
2. 译码分析指令操作码和地址码
3. 执行指令，取操作数、运算、存结果
4. 计算下一条指令地址（PC + 1 或跳转）

**特点**：
- 指令和数据用二进制表示
- 指令由操作码和地址码组成
- 以运算器为中心（现代计算机已改为以存储器为中心）

### 1.3 现代计算机结构

以存储器为中心的现代计算机结构：

```
输入设备 → 存储器 ←→ 运算器 ←→ 控制器 → 输出设备
              ↑                        ↑
              └──────── CPU ───────────┘
```

- **CPU** = 运算器 + 控制器 + 高速缓存（Cache）
- **主机** = CPU + 主存储器
- **外部设备** = 输入设备 + 输出设备 + 辅助存储器

### 1.4 计算机层次结构

```
┌──────────────────────────────────────┐
│  应用层（应用程序）                    │
├──────────────────────────────────────┤
│  高级语言层（C、Java、Python）          │
├──────────────────────────────────────┤
│  汇编语言层（指令集架构 ISA）           │
├──────────────────────────────────────┤
│  操作系统层（OS、资源管理、中断处理）    │
├──────────────────────────────────────┤
│  指令系统层（机器指令、微指令）          │
├──────────────────────────────────────┤
│  微体系结构层（数据通路、控制逻辑）      │
├──────────────────────────────────────┤
│  数字逻辑层（门电路、触发器、寄存器）    │
└──────────────────────────────────────┘
```

**ISA（指令集架构）** 是软件和硬件之间的接口，规定了指令格式、寻址方式、数据类型等。

### 1.5 计算机性能指标

- **吞吐量（Throughput）**：单位时间内完成的任务数量
- **响应时间（Response Time）**：任务从提交到完成的总时间
- **CPI（Cycles Per Instruction）**：执行每条指令所需的时钟周期数
  - `CPU 时间 = 指令条数 × CPI × 时钟周期时间`
- **MIPS（Million Instructions Per Second）**：`MIPS = 主频(MHz) / CPI`
- **FLOPS（Floating-point Operations Per Second）**：浮点运算性能
- **Amdahl 定律**：系统加速比受限于可改进部分的比例
  - `加速比 = 1 / ((1 - P) + P/S)`，其中 P 为可改进比例，S 为改进倍数

## 二、数据表示

### 2.1 数制系统

| 进制 | 基数 | 数码 | 后缀 |
|------|------|------|------|
| 二进制 | 2 | 0, 1 | B |
| 八进制 | 8 | 0–7 | O / Q |
| 十进制 | 10 | 0–9 | D |
| 十六进制 | 16 | 0–9, A–F | H |

**进制转换**：
- 十进制 → 二进制：整数部分除 2 取余，小数部分乘 2 取整
- 二进制 → 十六进制：每 4 位一组转换
- 二进制 → 八进制：每 3 位一组转换

### 2.2 原码、反码、补码

**原码（Sign-Magnitude）**：
- 最高位为符号位（0 正 1 负），其余位表示数值
- 例子：`+5 = 0101`, `-5 = 1101`（4 位）
- 缺点：0 有两种表示（0000 和 1000），加减法复杂

**反码（Ones' Complement）**：
- 正数与原码相同，负数将原码除符号位外的各位取反
- 缺点：0 仍有两种表示

**补码（Two's Complement）**：
- 正数与原码相同，负数为反码 + 1
- `-x` 的补码 = `2^n - x`
- 优点：0 唯一表示，加减法统一用加法实现
- 表示范围：`-2^(n-1) ~ 2^(n-1) - 1`（n 位）

**补码运算规则**：
- `[X+Y]补 = [X]补 + [Y]补 (mod 2^n)`
- `[X-Y]补 = [X]补 + [-Y]补`
- 溢出判断：双符号位法（变形补码），最高位进位和次高位进位异或为 1 则溢出

### 2.3 定点数

- **定点整数**：小数点固定在最低位之后
- **定点小数**：小数点固定在最高位之后、符号位之前
- **表示范围有限**：n 位定点整数补码范围为 `-2^(n-1) ~ 2^(n-1) - 1`

### 2.4 浮点数（IEEE 754）

**IEEE 754 标准格式**：

```
V = (-1)^S × M × 2^E
```

| 类型 | 总位数 | 符号位(S) | 阶码(E) | 尾数(M) | 偏置值(Bias) |
|------|--------|-----------|---------|---------|--------------|
| float (单精度) | 32 | 1 | 8 | 23 | 127 |
| double (双精度) | 64 | 1 | 11 | 52 | 1023 |

**规格化浮点数**：
- **单精度**：`(-1)^S × 1.M × 2^(E-127)`
- 尾数首位隐含为 1（节省 1 位），称为"隐藏位"
- 阶码用移码表示，E 的取值范围：1 ~ 254（单精度），1 ~ 2046（双精度）

**特殊值**：

| 符号位 S | 阶码 E | 尾数 M  | 含义        |
|----------|--------|---------|-------------|
| 0/1      | 全 1   | 全 0    | 无穷大 ±∞   |
| 0/1      | 全 1   | 非全 0  | NaN         |
| 0/1      | 全 0   | 全 0    | 0           |
| 0/1      | 全 0   | 非全 0  | 非规格化数（Denormalized） |

**非规格化数**：阶码全 0 时，表示 `(-1)^S × 0.M × 2^(-126)`（单精度），用于表示接近 0 的极小值。

**浮点数运算步骤**：
1. **对阶**：小阶向大阶看齐，尾数右移
2. **尾数运算**：对阶后的尾数进行加减
3. **规格化**：左规或右规
4. **舍入**：0 舍 1 入 / 恒舍 / 恒置 1
5. **溢出判断**：阶码是否超出表示范围

### 2.5 非数值数据表示

- **ASCII**：7 位编码，共 128 个字符
- **Unicode**：统一字符编码，UTF-8、UTF-16、UTF-32 等编码方案
- **汉字编码**：GB2312、GBK、GB18030
- **校验码**：奇偶校验、CRC 循环冗余校验、汉明码（纠错码）

## 三、运算器

### 3.1 算术逻辑单元（ALU）

ALU 是运算器的核心部件，实现算术和逻辑运算。

**功能**：
- **算术运算**：加、减、乘、除、加 1、减 1、求补
- **逻辑运算**：与、或、非、异或、逻辑移位
- **比较运算**：大于、小于、等于

**结构**：
```
输入 A ─┐      ┌─ 结果输出
         ├─ ALU ┤
输入 B ─┘      ├─ 标志输出（CF、ZF、SF、OF）
控制信号 ──────┘
```

**标志位寄存器**：
- **CF（Carry Flag）**：进位/借位标志
- **ZF（Zero Flag）**：结果为零标志
- **SF（Sign Flag）**：符号标志（结果最高位）
- **OF（Overflow Flag）**：溢出标志

### 3.2 加法器

**半加器（Half Adder）**：
- 两个输入 A、B，输出 S（和）、C（进位）
- `S = A ⊕ B`，`C = A ∧ B`

**全加器（Full Adder）**：
- 三个输入 A、B、Ci（低位进位），输出 S、Co（高位进位）
- `S = A ⊕ B ⊕ Ci`，`Co = (A ∧ B) ∨ (A ∧ Ci) ∨ (B ∧ Ci)`

**行波进位加法器（Ripple Carry Adder, RCA）**：
- n 个全加器串联，进位逐位传递
- **延迟高**：延迟 ≈ n × 全加器进位延迟

**先行进位加法器（Carry Look-ahead Adder, CLA）**：
- 通过逻辑电路提前计算进位，消除进位传递延迟
- 进位公式：
  - `Gi = Ai ∧ Bi`（生成信号 Generate）
  - `Pi = Ai ⊕ Bi`（传播信号 Propagate）
  - `Ci+1 = Gi ∨ (Pi ∧ Ci)`
- 4 位 CLA 可在 3 级门延迟内完成加法

**超前进位加法器**进一步扩展到 16 位、32 位，通常采用**分组并行进位**策略。

### 3.3 乘法器

**原码乘法**：
- 符号位单独处理：异或运算
- 数值部分用无符号乘法
- 手工乘法展开：移位相加

**补码乘法（Booth 算法）**：
- 直接对补码进行乘法运算，无需处理符号
- 两位 Booth 算法：一次扫描 3 位（当前位 + 前一位），减少部分积数量
- Booth 编码规则：

| Yi Yi-1 | 操作 |
|----------|------|
| 00 | 加 0 |
| 01 | 加 X |
| 10 | 减 X |
| 11 | 加 0 |

**阵列乘法器**：利用硬件阵列并行计算所有部分积并求和，速度快但面积大。

**快速乘法器**：Booth 编码 + Wallace 树（压缩部分积）+ 先行进位加法器。

### 3.4 除法器

**恢复余数法（Restoring Division）**：
- 每次减去除数，若结果为负则恢复原值
- 需要额外恢复步骤，效率较低

**不恢复余数法（Non-restoring Division）**：
- 根据余数符号决定下一步操作（加或减）
- 比恢复余数法快一倍

**阵列除法器**：类似阵列乘法器，用硬件阵列实现除法。

**SRT 除法**：现代 CPU 使用的高性能除法算法，用查找表预测商的每位，提高并行度。

## 四、存储器

### 4.1 存储器层次结构

计算机利用**局部性原理（Principle of Locality）**构建存储层次：

```
CPU 寄存器       （速度最快，容量最小，成本最高）
       ↓
L1 Cache（SRAM）  （~1ns，数十 KB）
       ↓
L2 Cache（SRAM）  （~5ns，数百 KB ~ 数 MB）
       ↓
L3 Cache（SRAM）  （~15ns，数 MB ~ 数十 MB）
       ↓
主存 RAM（DRAM）  （~50ns，GB 级别）
       ↓
SSD/磁盘         （~ms 级别，TB 级别）
```

**局部性原理**：
- **时间局部性**：刚刚访问过的数据很可能再次被访问
- **空间局部性**：访问某个地址后，邻近地址也很可能被访问

### 4.2 半导体存储器

**SRAM（静态随机存取存储器）**：
- 用触发器存储信息，6 晶体管/位
- **速度快**，不需刷新
- 用于 Cache

**DRAM（动态随机存取存储器）**：
- 用电容存储信息，1 晶体管 + 1 电容/位
- **密度高**、成本低，但需要定期刷新（~64ms）
- 用于主存

**DRAM 刷新方式**：
- 集中刷新
- 分散刷新
- 异步刷新

**ROM（只读存储器）**：
- **ROM**：掩模编程，出厂固定
- **PROM**：可一次编程
- **EPROM**：紫外线可擦写
- **EEPROM**：电可擦写
- **Flash Memory**：快闪存储器，EEPROM 的变种，广泛用于 SSD 和 U 盘

### 4.3 主存储器

**基本结构**：
```
地址总线 → 地址译码器 → 存储矩阵 ←→ 读写电路 ←→ 数据总线
```

**存储芯片扩展**：
- **位扩展**：多个芯片并联，地址线共用，数据线分别连接
- **字扩展**：多个芯片串联，地址线高位译码片选
- **字位扩展**：同时进行位和字的扩展

**存储带宽**：
- `带宽 = 数据总线宽度 × 工作频率`

**多体交叉存储器（Interleaved Memory）**：
- 将主存分为多个独立存储体（Bank）
- 连续地址分布在不同的 Bank 中
- 支持流水式访问，提高带宽

### 4.4 Cache

**基本概念**：
- Cache 位于 CPU 和主存之间，对程序员透明
- 以 **Cache 行（Block）** 为单位进行数据交换
- Cache 容量远小于主存，通过映射机制实现地址转换

**地址映射方式**：

| 映射方式 | 特点 | 优缺点 |
|----------|------|--------|
| 直接映射 | 每个主存块只能映射到固定 Cache 行 | 简单、冲突率高 |
| 全相联映射 | 可映射到任意 Cache 行 | 灵活、查找慢 |
| 组相联映射 | 分若干组，组内全相联，组间直接映射 | 折中方案 |

**n 路组相联**：每组包含 n 个 Cache 行，常见的有 2 路、4 路、8 路组相联。

**替换算法**：
- **LRU（Least Recently Used）**：替换最久未使用的行
- **FIFO（First In First Out）**：替换最先进入的行
- **LFU（Least Frequently Used）**：替换使用频率最低的行
- **随机替换**：随机选择一行替换

**写策略**：
- **写直达（Write Through）**：同时写 Cache 和主存
- **写回（Write Back）**：仅写 Cache，被替换时写回主存（需脏位 Dirty Bit）
- **写分配（Write Allocate）**：写不命中时将块调入 Cache
- **非写分配（No Write Allocate）**：写不命中时直接写主存

**Cache 性能公式**：
`平均访问时间 = 命中时间 + 缺失率 × 缺失代价`

### 4.5 虚拟存储器

**概念**：
- 虚拟存储器将主存和磁盘统一编址，使程序可以使用比物理内存更大的地址空间
- 由操作系统和 MMU（Memory Management Unit）共同管理

**实现方式**：

| 方式 | 原理 | 特点 |
|------|------|------|
| 页式 | 固定大小页面（4KB 典型） | 无外部碎片、有内部碎片 |
| 段式 | 按逻辑分段（代码段、数据段等） | 有外部碎片、便于共享保护 |
| 段页式 | 段内分页 | 兼具两者优点 |

**页表（Page Table）**：
- 虚拟地址 → 物理地址的映射表
- 每页一个页表项（PTE），包含物理页框号、有效位、访问位、脏位等

**快表（TLB, Translation Lookaside Buffer）**：
- Cache 中的页表项缓存
- 利用局部性原理加速地址转换
- TLB 缺失时需查页表（可能产生缺页中断）

**缺页中断（Page Fault）**：
- 访问的页面不在主存中时触发
- 从磁盘调入页面，可能触发页面置换
- **页面置换算法**：OPT（理想）、LRU、FIFO、Clock（NRU）

**多级页表**：
- 解决大地址空间下连续页表过大的问题
- x86-64 使用 4 级页表（PML4 → PDPT → PD → PT）

## 五、指令系统

### 5.1 指令格式

指令由 **操作码（Opcode）** 和 **地址码（Operand Address）** 组成：

```
指令 = 操作码 + 地址码
```

**按地址码数量分类**：

| 类型 | 格式 | 示例 |
|------|------|------|
| 三地址指令 | OP A1, A2, A3 | ADD R1, R2, R3 |
| 二地址指令 | OP A1, A2 | ADD R1, R2 |
| 一地址指令 | OP A1 | INC R1 |
| 零地址指令 | OP | NOP, HLT |

**操作码编码**：
- **定长操作码**：操作码位数固定，译码简单
- **变长操作码**：使用扩展操作码技术，缩短常用指令操作码
- **扩展操作码原则**：短操作码不能是长操作码的前缀

### 5.2 数据寻址方式

寻址方式决定如何计算操作数的有效地址：

| 寻址方式 | 有效地址 | 特点 |
|----------|----------|------|
| 立即寻址 | 指令直接给出操作数 | 速度快，数值范围受限 |
| 寄存器寻址 | 操作数在寄存器中 | 最快，无访存 |
| 直接寻址 | EA = A（指令中地址码） | 简单，地址范围有限 |
| 间接寻址 | EA = (A) | 灵活，两次访存 |
| 寄存器间接寻址 | EA = (R) | 一次访存，灵活 |
| 基址寻址 | EA = (BR) + A | 支持程序重定位 |
| 变址寻址 | EA = A + (IX) | 适合数组和循环 |
| 相对寻址 | EA = (PC) + A | 用于转移指令 |

### 5.3 指令类型

- **数据传输**：MOV、LD、ST、PUSH、POP
- **算术运算**：ADD、SUB、MUL、DIV、INC、DEC
- **逻辑运算**：AND、OR、XOR、NOT、SHL、SHR
- **控制转移**：JMP、JZ/JNZ、CALL、RET
- **输入输出**：IN、OUT
- **系统控制**：HLT、INT、IRET

### 5.4 CISC 与 RISC

| 特性 | CISC | RISC |
|------|------|------|
| 指令数量 | 多（数百条） | 少（数十 ~ 百余条） |
| 指令长度 | 可变 | 固定（通常 32 位） |
| 指令格式 | 多种格式 | 少量格式，规整 |
| 寻址方式 | 多（十几种） | 少（几种） |
| 访存指令 | 允许算术指令直接访存 | 只有 LD/ST 访存 |
| 寄存器 | 较少 | 多（通常 ≥ 32 个） |
| 控制逻辑 | 微程序控制为主 | 硬布线控制为主 |
| CPI | 大、变化大 | 小、接近 1 |
| 编译器 | 相对简单 | 需要优化编译器 |
| 典型架构 | x86 | ARM、MIPS、RISC-V |

**现代趋势**：CISC 和 RISC 正在融合 —— CISC 处理器内部将 x86 指令译码为类 RISC 的微操作（如 Intel Core 系列）。x86 是 CISC 外观 + RISC 内核的混合体。

## 六、CPU

### 6.1 CPU 基本结构

```
┌─────────────────────────────────────┐
│              CPU                    │
│  ┌──────────┐  ┌──────────────────┐ │
│  │  寄存器   │  │    控制器        │ │
│  │  PC, IR  │  │  取指 → 译码     │ │
│  │  GPRs    │  │  → 执行 → 写回    │ │
│  │  PSW/FLAGS│  └──────────────────┘ │
│  └──────────┘                        │
│  ┌──────────────────────────────────┐│
│  │        数据通路 (Datapath)       ││
│  │  ALU → 寄存器 → 总线 → MUX      ││
│  └──────────────────────────────────┘│
│  ┌──────────────────────────────────┐│
│  │     Cache（L1 I / L1 D）        ││
│  └──────────────────────────────────┘│
└─────────────────────────────────────┘
```

**主要寄存器**：
- **PC（程序计数器）**：存放下一条指令的地址
- **IR（指令寄存器）**：存放当前正在执行的指令
- **MAR（存储器地址寄存器）**：与地址总线相连
- **MDR（存储器数据寄存器）**：与数据总线相连
- **GPRs（通用寄存器组）**：暂存操作数和结果
- **PSW（程序状态字）**：标志位（CF、ZF、SF、OF 等）

### 6.2 数据通路（Datapath）

数据通路是 CPU 中各部件之间的数据传递路径，决定了指令执行的效率。

**单总线数据通路**：
- 所有部件通过单一总线连接
- 结构简单，但一次只能传输一个数据，性能受限
- 每个 ALU 操作至少需要 3 个时钟周期（A→总线、B→总线、结果输出）

**多总线数据通路**：
- 使用多条总线（如 A 总线、B 总线、结果总线）
- 可并行传输多个数据，提高吞吐量

**专用通路数据通路**：
- 为特定数据流设计专用连接
- 速度最快，但硬件开销大

### 6.3 控制单元

**硬布线控制（Hardwired Control）**：
- 用组合逻辑电路实现控制信号生成
- **优点**：速度快（RISC 常用）
- **缺点**：设计复杂，不易修改

**微程序控制（Microprogrammed Control）**：
- 将控制信号编码为"微指令"存储在控制存储器（Control Store）中
- **优点**：灵活，易于修改和扩展（CISC 常用）
- **缺点**：速度较慢（需读取微指令）

**微程序控制概念**：
- **微命令**：控制门电路开/关的最小信号
- **微操作**：一个微命令执行的操作
- **微指令**：一组微命令的集合
- **微程序**：一系列微指令构成一个机器指令的执行序列

**微指令编码方式**：
- **直接编码**：每位对应一个微命令，并行度高
- **字段直接译码**：将微命令分组，组内互斥，组间并行
- **字段间接译码**：通过一个字段译码控制另一个字段

### 6.4 指令执行周期

一条指令的执行过程：

| 阶段 | 操作 | 说明 |
|------|------|------|
| **取指（IF）** | PC → MAR → 读内存 → MDR → IR, PC+1 | 从内存取出指令 |
| **译码（ID）** | IR → 控制器译码, 取操作数 | 分析操作码和操作数 |
| **执行（EX）** | ALU 执行运算或计算地址 | 具体运算 |
| **访存（MEM）** | 读/写主存（仅访存指令需要） | 数据存取 |
| **写回（WB）** | 结果写入目标寄存器 | 保存结果 |

### 6.5 流水线（Pipeline）

**流水线基本思想**：
- 将指令执行过程分为多个阶段，各阶段重叠执行不同指令
- 理想情况下，流水线 CPI ≈ 1

**经典 5 级流水线**：

```
时钟:  1   2   3   4   5   6   7   8
I1:   IF  ID  EX  MEM WB
I2:       IF  ID  EX  MEM WB
I3:           IF  ID  EX  MEM WB
I4:               IF  ID  EX  MEM WB
```

**流水线冒险（Hazard）**：

| 冒险类型 | 原因 | 解决方法 |
|----------|------|----------|
| **结构冒险** | 硬件资源冲突 | 分离指令/数据 Cache、资源复制 |
| **数据冒险** | 指令间数据依赖 | 转发（Forwarding/Bypassing）、插入气泡、调整指令顺序 |
| **控制冒险** | 分支指令改变 PC | 分支预测、延迟分支、分支目标缓冲（BTB） |

**数据冒险三种情况**：
- **RAW（Read After Write）**：写后读 —— 真正的数据依赖
- **WAR（Write After Read）**：读后写 —— 名相关（寄存器重命名解决）
- **WAW（Write After Write）**：写后写 —— 名相关（寄存器重命名解决）

**流水线性能**：
- `理想加速比 = 流水线段数`
- 实际加速比受冒险、不完美平衡等影响
- `流水线吞吐率 = 指令数 / 总执行时间`

**超流水线（Superpipeline）**：
- 将流水线段进一步细分，提高主频
- 每个阶段延迟更小，但冒险更复杂

**超标量（Superscalar）**：
- 一个时钟周期内发射多条指令
- 需要多个功能单元（多 ALU、多 FPU）
- 指令发射逻辑复杂，需乱序执行支持

**超长指令字（VLIW）**：
- 编译器将多个操作打包成一条长指令
- 硬件简化，但依赖编译器优化

### 6.6 乱序执行（Out-of-Order Execution）

**基本思想**：指令不按程序顺序执行，而是等操作数就绪后立即执行。

**关键组件**：
- **保留站（Reservation Station）**：暂存等待执行的指令
- **重排序缓冲（Reorder Buffer, ROB）**：按程序顺序提交结果
- **寄存器重命名**：消除名相关（WAR、WAW）

**Tomasulo 算法**：
- IBM 360/91 首次使用的乱序执行算法
- 通过保留站 + 公共数据总线（CDB）实现
- 现代处理器广泛使用的核心思想

### 6.7 分支预测（Branch Prediction）

**静态预测**：
- 总是预测跳转 / 总是预测不跳转
- 后向跳转预测取（循环）、前向跳转预测不取

**动态预测**：
- **1 位预测器**：记录上一次跳转结果
- **2 位饱和计数器**：状态机（Strongly Taken → Weakly Taken → Weakly Not Taken → Strongly Not Taken）
- **分支历史表（BHT）**：用 PC 低位索引，存放预测位

**全局预测（Gshare）**：
- 使用全局历史寄存器（GHR）与 PC 异或后索引
- 考虑分支之间的相关性

**分支目标缓冲（BTB）**：
- 缓存分支指令地址和目标地址
- 在 IF 阶段即可预测并跳转，消除分支延迟

## 七、总线

### 7.1 总线基本概念

**总线（Bus）** 是连接计算机各部件的一组公共信号线，是系统通信的骨干。

**总线分类**：

| 按层次 | 说明 |
|--------|------|
| **片内总线** | CPU 芯片内部各功能单元之间的连接 |
| **系统总线** | CPU、主存、I/O 接口之间的总线 |
| **I/O 总线** | 连接外部设备的总线 |

**系统总线按功能分为三组**：

| 总线类型 | 功能 | 方向 |
|----------|------|------|
| **数据总线（Data Bus）** | 传输数据信息 | 双向 |
| **地址总线（Address Bus）** | 传输地址信息 | 单向（CPU→外设） |
| **控制总线（Control Bus）** | 传输控制/状态信号 | 双向 |

### 7.2 总线仲裁

多个主设备竞争总线时，需要仲裁决定使用权。

**集中式仲裁**：

| 方式 | 原理 | 特点 |
|------|------|------|
| **链式查询** | 优先权从高到低链式传递 | 简单、对故障敏感 |
| **计数器查询** | 设备号计数器递增查询 | 灵活、需额外计数线 |
| **独立请求** | 每个设备有独立请求/允许线 | 速度快、硬件复杂 |

**分布式仲裁**：
- 所有设备共同决定总线使用权
- 每个设备有唯一的优先级编码
- 通过仲裁总线实现"线与"逻辑

### 7.3 总线操作与定时

**总线周期**：
1. **申请阶段**：主设备申请总线
2. **寻址阶段**：主设备发送地址和命令
3. **传输阶段**：主从设备进行数据交换
4. **结束阶段**：释放总线

**总线定时方式**：

| 方式 | 原理 | 特点 |
|------|------|------|
| **同步总线** | 公共时钟控制所有传输 | 简单、但所有设备必须同速 |
| **异步总线** | 握手信号控制传输 | 适应不同速设备、复杂 |
| **半同步** | 同步 + WAIT 信号插入等待周期 | 折中方案 |

### 7.4 总线标准

**常见总线标准**：

| 总线 | 宽度 | 带宽 | 特点 |
|------|------|------|------|
| **PCI** | 32/64 位 | 133 MB/s ~ 533 MB/s | 并行、热插拔 |
| **PCI Express (PCIe)** | 1~16 通道 | 每通道 ~1 GB/s (Gen3) | 串行、点对点、高速 |
| **USB** | 串行 | 5 Gbps (USB 3.0) | 外设总线、热插拔 |
| **SATA** | 串行 | 6 Gbps (SATA 3.0) | 磁盘接口 |
| **NVMe** | PCIe 通道 | 数 GB/s | SSD 高速接口 |

**PCIe 特点**：
- 采用差分信号传输，抗干扰能力强
- 点对点连接，不共享带宽
- 支持多通道捆绑（×1、×4、×8、×16）
- 支持热插拔和电源管理

## 八、输入输出系统

### 8.1 I/O 系统概述

I/O 设备分类：

| 分类 | 举例 | 特点 |
|------|------|------|
| **字符设备** | 键盘、鼠标、打印机 | 以字符为单位传输 |
| **块设备** | 磁盘、SSD、光盘 | 以数据块为单位传输 |
| **网络设备** | 网卡 | 帧/包为单位传输 |

I/O 接口功能：
- **地址译码**：识别设备地址
- **数据缓冲**：速度匹配
- **格式转换**：串行 ↔ 并行、电平转换
- **控制逻辑**：执行命令、状态反馈
- **中断管理**：产生和处理中断信号

### 8.2 I/O 控制方式

#### 程序查询方式（Programmed I/O）

- CPU 不断查询设备状态（轮询）
- **优点**：实现简单
- **缺点**：CPU 利用率极低（忙等待）

```
LOOP: 测试设备状态
      若未就绪 → 跳转 LOOP
      若就绪 → 读/写数据
```

#### 中断方式（Interrupt-driven I/O）

- 设备主动向 CPU 发中断请求
- CPU 暂停当前程序，执行中断服务程序
- **优点**：提高 CPU 利用率
- **缺点**：每次中断需保存/恢复上下文，开销较大

**中断处理流程**：
1. 中断请求（设备发送中断信号）
2. 中断判优（多个中断同时发生时决定优先级）
3. 中断响应（CPU 保存 PC 和 PSW，关中断）
4. 中断服务（转中断向量 → 执行 ISR）
5. 中断返回（恢复现场，开中断，返回原程序）

**中断优先级**：
- 多级中断支持中断嵌套（高优先级可打断低优先级中断）
- 向量中断：设备直接提供中断向量（ISR 地址）
- 中断控制器（如 8259A）：管理多个中断源

#### DMA 方式（Direct Memory Access）

- DMA 控制器直接在 I/O 设备和内存之间传输数据，无需 CPU 参与
- **优点**：传输大量数据时 CPU 开销极小
- 多用于磁盘、网卡、GPU 等高速设备

**DMA 传输步骤**：
1. **预处理**：CPU 设置 DMA 控制器（源地址、目标地址、传输长度、方向）
2. **数据传输**：DMA 控制器接管总线，在 I/O 和内存间传输数据
3. **后处理**：传输完成，DMA 发送中断通知 CPU

**DMA 总线占用方式**：
- **成组传送（Burst Mode）**：DMA 连续占用总线，传输整块数据
- **周期挪用（Cycle Stealing）**：DMA 在每个机器周期结束时占用一个总线周期
- **透明方式**：DMA 在 CPU 不访问总线时传输

**DMA 控制器结构**：
```
CPU ←→ DMA 控制器：命令寄存器、状态寄存器、地址寄存器、计数器
         ↓
       I/O 设备 ←→ 内存（数据总线直连）
```

#### 通道方式（Channel）

- **通道**是一种特殊的 I/O 处理器，可执行通道程序
- 独立管理 I/O 操作，CPU 只需发出 I/O 命令
- **选择通道**：一次控制一台设备（高带宽）
- **数组多路通道**：逐次传输数据块
- **字节多路通道**：交叉传输字节

### 8.3 常见 I/O 接口

| 接口 | 类型 | 特点 |
|------|------|------|
| **UART** | 串行 | 异步通信、RS-232 标准 |
| **SPI** | 串行 | 同步、全双工、主从模式 |
| **I²C** | 串行 | 同步、多主、双线（SCL + SDA） |
| **GPIO** | 并行 | 通用输入输出引脚 |
| **AHB/APB** | SoC 总线 | ARM AMBA 总线标准 |

### 8.4 I/O 性能指标

- **吞吐量**：单位时间内传输的数据量
- **延迟**：发起 I/O 请求到传输完成的时间
- **IOPS（I/O Operations Per Second）**：每秒 I/O 操作次数（重要指标）
- **CPU 占用率**：I/O 操作消耗的 CPU 时间比例

## 九、总结

计算机组成原理的核心思想可以概括为：**以存储程序为基础，以数据通路和控制逻辑为手段，以层次化结构来提高性能和降低成本**。

**关键理解**：
1. **层次化**：从数字逻辑到操作系统，每层封装复杂性
2. **局部性**：时间和空间局部性是 Cache、TLB、虚拟内存等机制的理论基础
3. **流水线**：指令级并行的核心，是现代高性能 CPU 的基石
4. **存储层次**：用 SRAM→DRAM→Disk 的层次在成本和速度之间取得平衡
5. **并行的多种形式**：位级并行、指令级并行（流水线/超标量）、线程级并行、数据级并行（SIMD）

**推荐学习路线**：
- 基础：数字逻辑、布尔代数、组合/时序电路
- 进阶：指令集架构（RISC-V / MIPS）、CPU 设计（Verilog/VHDL）
- 深入：超标量处理器、多核架构、GPU 体系结构
- 实践：使用 Logisim / Digital 仿真、FPGA 验证
