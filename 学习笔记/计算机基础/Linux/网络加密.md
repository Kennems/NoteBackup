# 网络加密

## HTTP vs HTTPS

| 协议  | 加密 | 默认端口 | 证书需求     | 安全性         |
| ----- | ---- | -------- | ------------ | -------------- |
| HTTP  | 无   | 80       | 无需         | 明文传输，易被窃听和篡改 |
| HTTPS | SSL/TLS | 443   | 需要CA签发的证书 | 加密传输，防窃听、防篡改、身份认证 |

## 对称加密 vs 非对称加密

| 特性       | 对称加密（AES等）         | 非对称加密（RSA等）         |
| ---------- | ------------------------- | --------------------------- |
| 密钥数量   | 1个密钥（加解密相同）     | 2个密钥（公钥+私钥）        |
| 加解密速度 | 快                        | 慢（约为对称加密的千分之一）  |
| 密钥分发   | 需要安全的密钥交换渠道    | 公钥可公开，私钥保密          |
| 典型应用   | 大量数据传输加密          | 数字签名、密钥交换、身份认证  |

**HTTPS 的典型工作流程**：
1. TCP 三次握手建立连接
2. TLS 握手：客户端发送支持的加密套件 → 服务器选择加密套件并发送证书 → 密钥交换 → 双方生成会话密钥
3. 使用对称加密算法（如 AES）加密后续通信内容

## 数字签名

数字签名是一种用于验证消息完整性、认证消息来源并防止否认的技术。它利用**非对称加密**实现：

1. 发送方使用**私钥**对消息的**哈希值**进行加密，生成数字签名
2. 接收方使用发送方的**公钥**解密签名得到哈希值，并与自己计算的哈希值比对
3. 哈希值一致 → 消息未被篡改且确实来自声称的发送方

常见的数字签名算法：RSA、ECDSA、Ed25519。

### 应用场景
- **证书验证**（SSL/TLS 证书链）
- **代码签名**（软件签名/更新）
- **电子签名**（文档签署）
- **区块链**（交易验证）
- **电子邮件**（DKIM/PGP 邮件签名）
