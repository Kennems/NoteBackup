# 嵌入式系统设计

## 嵌入式 Linux 概述

### 什么是嵌入式 Linux

嵌入式 Linux 是指将 Linux 操作系统裁剪、定制后部署在资源受限的嵌入式设备中运行的解决方案。与桌面/服务器 Linux 不同，嵌入式 Linux 需要针对特定硬件平台进行交叉编译，生成可在目标设备上运行的镜像。

### 交叉编译（Cross-Compilation）

- **定义**：在性能强大的宿主机（Host）上编译生成目标机（Target）可执行代码的过程。
- **原因**：嵌入式设备通常 CPU 性能弱、存储空间小、无完整开发环境，无法直接在设备上编译。
- **工具链（Toolchain）**：交叉编译需要一套完整的工具链，包含编译器、汇编器、链接器、调试器及标准库。
- **常见工具链**：
  - **GNU Toolchain**：gcc（编译器）、binutils（as、ld、objcopy、objdump）、glibc/uclibc/musl（C 库）
  - **Linaro Toolchain**：ARM 架构官方推荐的交叉工具链
  - **Buildroot 自建工具链**：通过 Buildroot 系统自动生成定制工具链
  - **crosstool-NG**：灵活的交叉工具链构建工具

### 交叉编译示例

```bash
# ARM 交叉编译 Hello World
arm-linux-gnueabihf-gcc -o hello hello.c

# 查看生成的目标文件信息
file hello
# 输出: ELF 32-bit LSB executable, ARM, EABI5 version 1 (SYSV)

# 使用静态链接避免动态库依赖
arm-linux-gnueabihf-gcc -static -o hello_static hello.c
```

### 嵌入式 Linux 系统组成

嵌入式 Linux 系统由以下四大部分组成：

1. **引导加载程序（Bootloader）** — 初始化硬件、加载内核
2. **Linux 内核（Kernel）** — 进程调度、内存管理、设备驱动、网络协议栈
3. **根文件系统（Root Filesystem）** — 提供系统运行所需的程序、库、配置
4. **应用程序（Application）** — 实现设备具体业务功能的用户空间程序

## 系统启动流程

### 完整启动链路

```
ROM Code → SPL (Secondary Program Loader) → U-Boot → Kernel → init → Application
```

### 各阶段详解

#### 1. ROM Code（片上引导代码）

- 固化在 SoC 内部的只读存储器（ROM）中，芯片出厂即存在，不可修改。
- 上电后 CPU 从复位向量指定的地址（通常为 0x00000000 或 0xFFFF0000）开始执行。
- 负责最基础的硬件初始化（时钟、PLL、SDRAM 控制器），然后将 SPL 从存储介质（NAND Flash、SD 卡、SPI Flash）加载到 SRAM 中执行。
- 对于不同厂商的 SoC，ROM Code 的加载协议不同，例如：
  - **Allwinner**：从 SD 卡第 8KB 偏移处加载 SPL
  - **TI OMAP**：检测启动引脚电平，选择从 NAND、MMC 或 UART 启动
  - **Rockchip**：支持从 eMMC 的 boot0/boot1 分区启动

#### 2. SPL / MLO（Secondary Program Loader）

- 第一级引导加载程序的次级阶段，通常称为 SPL 或 MLO（TI 平台称法）。
- 由于芯片内部 SRAM 通常很小（4KB ~ 256KB），SPL 必须精简。
- **职责**：
  - 初始化 DRAM 控制器，使外部 DDR 可用
  - 从存储介质加载完整的 U-Boot 到 DRAM
  - 跳转到 U-Boot 入口地址
- SPL 通常由 U-Boot 源码编译生成（`make <board>_defconfig && make spl`）。

#### 3. U-Boot（引导加载程序）

- 完整的二级引导加载程序，提供交互式命令行和脚本执行能力。
- **职责**：
  - 初始化外设（串口、网卡、MMC、USB）
  - 设置内核启动参数（bootargs）
  - 从网络（TFTP）、存储（FAT/EXT4）或 Flash 加载内核和设备树
  - 校验镜像完整性（SHA256、RSA 签名验证）
  - 跳转到内核入口执行

#### 4. Linux Kernel

- 内核解压自身，完成内存管理、进程调度、中断控制器和各子系统初始化。
- 挂载根文件系统（由 bootargs 中的 `root=` 参数指定）。
- 启动第一个用户空间进程（PID=1）。

#### 5. init 进程

- **传统 SysVinit**：按 `/etc/inittab` 定义的运行级别依次启动服务。
- **BusyBox init**：轻量级 init，适用于资源受限设备，读 `/etc/inittab` 启动 shell。
- **systemd**：现代 Linux 的 init 系统，使用并行启动、socket 激活、cgroup 管理。
- **OpenRC**：Gentoo 及其衍生系统使用，依赖关系由 shell 脚本管理。

### 启动参数（Bootargs）示例

```bash
# 通过 NFS 挂载根文件系统（开发阶段常用）
setenv bootargs console=ttyS0,115200 root=/dev/nfs nfsroot=192.168.1.100:/nfsroot ip=192.168.1.101

# 通过 MMC 分区挂载
setenv bootargs console=ttyS0,115200 root=/dev/mmcblk0p2 rootwait rw

# 通过 initramfs 使用内存中的根文件系统
setenv bootargs console=ttyS0,115200 rdinit=/sbin/init
```

## U-Boot

### 概述

U-Boot（Das U-Boot）是目前嵌入式 Linux 领域使用最广泛的引导加载程序，支持 ARM、RISC-V、x86、MIPS、PowerPC 等多种架构。源码托管在 [https://source.denx.de/u-boot/u-boot](https://source.denx.de/u-boot/u-boot)。

### 目录结构

```
u-boot/
├── arch/           # 架构相关代码（arch/arm/, arch/riscv/ 等）
├── board/          # 板级支持代码（板载初始化、DDR 配置等）
├── common/         # 通用函数（命令行解析、环境变量等）
├── cmd/            # 命令行命令实现
├── configs/        # 板级默认配置文件（*_defconfig）
├── dts/            # 设备树源文件及编译支持
├── drivers/        # 驱动（串口、网卡、MMC、USB、Flash 等）
├── fs/             # 文件系统支持（FAT、EXT4、UBIFS 等）
├── include/        # 头文件
├── net/            # 网络协议栈（TFTP、NFS、DHCP）
└── scripts/        # 构建脚本、Kconfig 配置系统
```

### 配置方法

U-Boot 在较新版本中使用 Kconfig 配置系统（与 Linux 内核类似），分为两个步骤：

```bash
# 第一步：选择板级默认配置
make <board>_defconfig

# 第二步：通过 menuconfig 进行个性化定制
make menuconfig
```

常见板级配置示例：

| 平台 | 配置命令 |
|------|----------|
| Raspberry Pi 3 | `make rpi_3_defconfig` |
| BeagleBone Black | `make am335x_evm_defconfig` |
| QEMU ARM virt | `make qemu_arm_defconfig` |
| SiFive HiFive Unleashed | `make sifive_fu540_defconfig` |

### 编译

```bash
# 设置交叉编译工具链前缀
export CROSS_COMPILE=arm-linux-gnueabihf-

# 指定目标架构
export ARCH=arm

# 编译（生成 u-boot.bin / u-boot.img / SPL）
make -j$(nproc)

# 查看生成的二进制文件
ls -lh u-boot.bin u-boot.img spl/u-boot-spl.bin
```

### 烧写方法

不同平台的烧写方式差异较大：

```bash
# 1. SD 卡烧写（偏移量需与 SoC ROM Code 约定一致）
sudo dd if=u-boot-spl.bin of=/dev/sdb bs=1k seek=8
sudo dd if=u-boot.bin of=/dev/sdb bs=1k seek=40

# 2. SPI Flash 烧写（通过 U-Boot 自身更新）
tftp ${loadaddr} u-boot.bin
sf probe
sf erase 0x0 0x100000
sf write ${loadaddr} 0x0 ${filesize}

# 3. eMMC boot 分区烧写
mmc dev 1
mmc partconf 1 1 1 1
tftp ${loadaddr} u-boot.bin
mmc write ${loadaddr} 0x0 ${filesize}
```

### U-Boot 常用命令

```bash
# 环境变量操作
printenv                  # 打印所有环境变量
setenv bootdelay 5        # 设置启动延时
setenv bootargs '...'     # 设置内核启动参数
saveenv                   # 保存环境变量到存储介质

# 内存操作
md 0x80000000 20          # 显示指定地址内存内容（16进制 + ASCII）
mw 0x80000000 0xdeadbeef  # 写入内存

# 存储设备
mmc list                  # 列出 MMC 设备
mmc dev 0                 # 选择 MMC 设备
mmc read ${loadaddr} 0x800 0x2000  # 读取 MMC 到内存

# 网络操作
dhcp                      # 通过 DHCP 获取 IP 地址
tftp ${loadaddr} zImage   # 通过 TFTP 下载内核

# 启动内核
bootz ${loadaddr} - ${fdt_addr}   # 启动压缩的 zImage
bootm ${loadaddr}                  # 启动 uImage 格式
```

## Linux 内核

### 内核配置（Kconfig / menuconfig）

Linux 内核采用 Kconfig 配置系统和 Makefile 构建框架，支持近 20000 个配置选项。

```bash
# 设置环境
export ARCH=arm
export CROSS_COMPILE=arm-linux-gnueabihf-

# 配置内核
make <board>_defconfig        # 使用板级默认配置
make menuconfig               # 基于 ncurses 的菜单配置界面
make xconfig                  # 基于 Qt 的图形化配置界面

# 保存配置文件
make savedefconfig            # 生成精简的 defconfig 文件
cp .config arch/arm/configs/myboard_defconfig  # 保存为板级配置
```

### menuconfig 常用配置项

```
General setup ──────────────────────────────
  → Local version - append to kernel release
  → Kernel compression mode (Gzip / LZ4 / XZ)
  → Default hostname

Enable loadable module support ─────────────
  → Module unloading
  → Forced module unloading
  → Module versioning support

System Type ────────────────────────────────
  → ARM system type (选择具体 SoC 系列)
  → Processor Type

Device Drivers ─────────────────────────────
  → Serial driver support
  → SPI / I2C / GPIO support
  → MMC/SD/SDIO card support
  → Network device support
  → USB support
  → Watchdog Timer support
  → LED Support
  → DMA Engine support

File systems ───────────────────────────────
  → The Extended 4 (ext4) filesystem
  → Flash filesystem (UBIFS, JFFS2)
  → Pseudo filesystems (/proc, /sys, devtmpfs)
```

### 内核编译

```bash
# 编译内核镜像
make -j$(nproc) zImage      # 压缩的内核镜像
make -j$(nproc) uImage       # 带 U-Boot 头的内核镜像

# 编译设备树
make -j$(nproc) dtbs

# 编译内核模块
make -j$(nproc) modules

# 安装模块到根文件系统
make modules_install INSTALL_MOD_PATH=/path/to/rootfs

# 产出物说明
grep -PROFIT_FILE
# arch/arm/boot/zImage          ← 内核二进制
# arch/arm/boot/dts/*.dtb       ← 设备树二进制
# arch/arm/boot/uImage          ← U-Boot 格式内核

# 查看内核版本信息
strings arch/arm/boot/zImage | grep "Linux version"
```

### 设备树（Device Tree）

#### 概述

设备树是一种描述硬件信息的数据结构，用于替代旧版内核中硬编码的板级文件（board-*.c）。通过传递设备树二进制文件（DTB），使同一份内核镜像可以支持不同的硬件平台。

#### 设备树文件类型

| 扩展名 | 含义 | 说明 |
|--------|------|------|
| `.dts` | Device Tree Source | 设备树源文件（文本格式） |
| `.dtsi` | Device Tree Source Include | 设备树头文件（SoC 级公共定义） |
| `.dtb` | Device Tree Blob | 设备树二进制（编译产物） |
| `.dtbo` | Device Tree Blob Overlay | 设备树叠加层（运行时加载） |

#### 基础语法

```dts
/dts-v1/;

#include "soc.dtsi"

/ {
    model = "MyBoard";
    compatible = "vendor,myboard", "vendor,soc";

    chosen {
        stdout-path = &uart0;
        bootargs = "console=ttyS0,115200";
    };

    memory@80000000 {
        device_type = "memory";
        reg = <0x80000000 0x10000000>;  /* 256MB at 0x80000000 */
    };

    leds {
        compatible = "gpio-leds";
        led0: led@0 {
            label = "heartbeat";
            gpios = <&gpio1 0 GPIO_ACTIVE_HIGH>;
            linux,default-trigger = "heartbeat";
        };
    };

    uart0: serial@1c28000 {
        compatible = "ns16550a";
        reg = <0x01c28000 0x400>;
        interrupts = <0 1 IRQ_TYPE_LEVEL_HIGH>;
        clocks = <&clk_uart>;
        status = "okay";
    };
};
```

#### 编译设备树

```bash
# 将 dts/dtsi 编译为 dtb
dtc -I dts -O dtb -o myboard.dtb myboard.dts

# 反编译 dtb
dtc -I dtb -O dts -o myboard.dts myboard.dtb

# 使用内核源码中的 dtc
make arch/arm/boot/dts/vexpress-v2p-ca9.dtb
```

#### 设备树匹配规则

内核通过设备的 `compatible` 属性与驱动中的 `of_match_table` 进行匹配：

```c
static const struct of_device_id my_driver_ids[] = {
    { .compatible = "vendor,mydevice", },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, my_driver_ids);
```

## 根文件系统

### 概述

根文件系统是 Linux 系统启动后挂载的第一个文件系统，包含 `init` 程序、系统工具、库文件、配置文件、设备节点等。嵌入式系统中常用的根文件系统方案有 BusyBox、Buildroot、Yocto。

### BusyBox

#### 简介

BusyBox 是一个将 400+ 常用 Unix 命令合并为单一可执行文件的开源项目，被称为"嵌入式 Linux 的瑞士军刀"。它以极小的体积提供完整的 POSIX 用户空间环境。

```bash
# 下载与配置
wget https://busybox.net/downloads/busybox-1.36.1.tar.bz2
tar xf busybox-1.36.1.tar.bz2
cd busybox-1.36.1
export ARCH=arm
export CROSS_COMPILE=arm-linux-gnueabihf-
make menuconfig      # 选择需要的命令和功能（静态编译建议开启）
make -j$(nproc)      # 编译
make install         # 默认安装到 _install/ 目录
```

#### 构建最小根文件系统

```bash
# 创建必要目录结构
cd _install
mkdir -p proc sys dev etc/init.d mnt tmp var/log

# 创建 init 脚本
cat > etc/init.d/rcS << 'EOF'
#!/bin/sh
mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs none /dev
echo "BusyBox init started"
EOF
chmod +x etc/init.d/rcS

# 复制 C 库（动态链接时需将 glibc/musl 的 so 文件复制到 lib/）
cp -r /path/to/sysroot/lib .

# 打包为 initramfs（嵌入内核）
find . | cpio -o --format=newc > ../rootfs.cpio
gzip -9 ../rootfs.cpio

# 在内核配置中启用 initramfs
# General setup → Initramfs source file → 指定 rootfs.cpio.gz 路径
```

### Buildroot

#### 简介

Buildroot 是一个高度自动化的嵌入式 Linux 构建系统，通过 Kconfig 配置界面一站式生成交叉工具链、根文件系统、内核镜像和引导加载程序。

#### 使用流程

```bash
# 下载
wget https://buildroot.org/downloads/buildroot-2024.02.tar.gz
tar xf buildroot-2024.02.tar.gz
cd buildroot-2024.02

# 配置（支持 200+ 官方板级配置）
make qemu_arm_vexpress_defconfig   # QEMU ARM 平台示例
make menuconfig                     # 定制包选择、文件系统格式等

# 编译（自动下载源码、交叉编译、打包镜像）
make -j$(nproc)

# 产出物位于 output/images/
ls output/images/
# rootfs.ext2  rootfs.tar  zImage  vexpress-v2p-ca9.dtb

# 支持的根文件系统格式
# ext2/3/4、squashfs、jffs2、ubifs、initramfs、cpio、tar
```

#### Buildroot 目录结构

```
buildroot/
├── board/           # 板级配置文件和 overlays
├── boot/            # 引导加载程序（u-boot、grub、barebox）
├── configs/         # 板级默认 defconfig
├── dl/              # 下载的源码包缓存
├── fs/              # 文件系统生成框架
├── linux/           # Linux 内核构建规则
├── output/          # 编译输出目录
│   ├── build/       # 各个包解压和编译目录
│   ├── host/        # 主机工具和交叉工具链
│   ├── images/      # 最终镜像
│   └── target/      # 目标根文件系统目录
├── package/         # 软件包构建规则（u-boot、openssh、nodejs 等）
└── toolchain/       # 工具链生成配置
```

### Yocto

#### 简介

Yocto 是一个企业级的嵌入式 Linux 构建框架，使用 OpenEmbedded（OE）构建系统，通过 BitBake 任务调度引擎执行构建。相比 Buildroot，Yocto 更强大也更复杂，适合商业级产品开发。

#### 核心概念

| 概念 | 说明 |
|------|------|
| **Recipe（配方）** | `.bb` 文件，描述如何下载、配置、编译和安装一个软件包 |
| **Layer（层）** | 组织 recipe、配置和补丁的目录结构 |
| **Machine（机器）** | 目标硬件平台的配置描述 |
| **Distribution（发行版）** | 系统级配置策略（特性、初始化系统等） |
| **BitBake** | Python 编写的构建引擎，解析 recipe 并调度任务 |
| **Image（镜像）** | 定义将哪些包打包到根文件系统中的 recipe |

#### 使用流程

```bash
# 安装 Yocto 所需依赖（Ubuntu/Debian）
sudo apt install gawk wget git diffstat unzip texinfo \
  gcc build-essential chrpath socat cpio python3 python3-pip \
  python3-pexpect xz-utils debianutils iputils-ping

# 下载（以 poky 参考发行版为例）
git clone git://git.yoctoproject.org/poky
cd poky

# 初始化构建环境
source oe-init-build-env build_arm

# 编辑配置
vi conf/local.conf
# 关键配置项：
# MACHINE ?= "raspberrypi3"        ← 目标平台
# DISTRO ?= "poky"                  ← 发行版
# DL_DIR ?= "/path/to/downloads"   ← 源码缓存目录

# 构建内核镜像
bitbake core-image-minimal         # 最小系统镜像
bitbake core-image-full-cmdline    # 完整命令行镜像
bitbake core-image-sato            # 含 X11 + Sato 桌面的镜像

# 生成 SDK（交叉编译工具链 + 头文件 + 库）
bitbake core-image-minimal -c populate_sdk
# SDK 安装脚本位于 tmp/deploy/sdk/ 目录
```

#### Yocto 常用命令

```bash
# 构建指定软件包
bitbake openssh

# 列出可用的镜像目标
ls meta*/recipes-core/images/

# 查找包含某个包的 recipe
bitbake -s | grep busybox

# 清理重建
bitbake busybox -c clean
bitbake busybox -c cleanall    # 包含下载的源码缓存

# 进入开发 shell
bitbake linux-yocto -c devshell
```

## 设备驱动程序

### 概述

Linux 设备驱动是内核与硬件之间的桥梁，所有对外设的访问都必须通过驱动程序完成。驱动以模块（.ko）形式或编译进内核的形式存在。

### 驱动类型

#### 1. 字符设备驱动

字符设备以字节流方式进行读写，是最常见的设备驱动类型（串口、GPIO、温度传感器等）。

```c
#include <linux/module.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>
#include <linux/uaccess.h>

#define DEVICE_NAME "my_char_dev"
#define CLASS_NAME  "my_class"

static int major;
static struct class *my_class;
static struct cdev my_cdev;
static char device_buffer[256];

static int my_open(struct inode *inode, struct file *filp) {
    pr_info("Device opened\n");
    return 0;
}

static int my_release(struct inode *inode, struct file *filp) {
    pr_info("Device closed\n");
    return 0;
}

static ssize_t my_read(struct file *filp, char __user *buf,
                       size_t count, loff_t *f_pos) {
    size_t len = strlen(device_buffer);
    if (*f_pos >= len) return 0;
    if (count > len - *f_pos) count = len - *f_pos;
    if (copy_to_user(buf, device_buffer + *f_pos, count))
        return -EFAULT;
    *f_pos += count;
    return count;
}

static ssize_t my_write(struct file *filp, const char __user *buf,
                        size_t count, loff_t *f_pos) {
    if (count > sizeof(device_buffer) - 1)
        count = sizeof(device_buffer) - 1;
    if (copy_from_user(device_buffer, buf, count))
        return -EFAULT;
    device_buffer[count] = '\0';
    *f_pos += count;
    pr_info("Received: %s\n", device_buffer);
    return count;
}

static struct file_operations fops = {
    .owner   = THIS_MODULE,
    .open    = my_open,
    .release = my_release,
    .read    = my_read,
    .write   = my_write,
};

static int __init my_init(void) {
    dev_t dev;

    // 动态分配主设备号
    alloc_chrdev_region(&dev, 0, 1, DEVICE_NAME);
    major = MAJOR(dev);

    // 初始化并添加字符设备
    cdev_init(&my_cdev, &fops);
    cdev_add(&my_cdev, dev, 1);

    // 创建 /sys/class/ 目录和 /dev/ 设备节点
    my_class = class_create(CLASS_NAME);
    device_create(my_class, NULL, dev, NULL, DEVICE_NAME);

    pr_info("Module loaded, major=%d\n", major);
    return 0;
}

static void __exit my_exit(void) {
    dev_t dev = MKDEV(major, 0);

    device_destroy(my_class, dev);
    class_destroy(my_class);
    cdev_del(&my_cdev);
    unregister_chrdev_region(dev, 1);

    pr_info("Module unloaded\n");
}

module_init(my_init);
module_exit(my_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Embedded Engineer");
MODULE_DESCRIPTION("Simple character device driver example");
```

#### 2. Platform 驱动

Platform 驱动（平台驱动）是 Linux 设备驱动模型中用于管理非枚举型总线设备（大多数 SoC 内部外设）的机制，与设备树结合使用。

```c
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/of.h>
#include <linux/of_device.h>

struct my_platform_data {
    int  irq_num;
    u32  reg_base;
    bool enable_feature;
};

static int my_probe(struct platform_device *pdev) {
    struct device *dev = &pdev->dev;
    struct my_platform_data *pdata;
    struct resource *res;

    dev_info(dev, "Probing device\n");

    // 从设备树获取资源
    res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
    if (!res) return -ENXIO;

    pdata = devm_kzalloc(dev, sizeof(*pdata), GFP_KERNEL);
    if (!pdata) return -ENOMEM;

    pdata->reg_base = res->start;

    // 从设备树获取中断号
    pdata->irq_num = platform_get_irq(pdev, 0);
    if (pdata->irq_num < 0) return pdata->irq_num;

    // 读取设备树中的自定义属性
    pdata->enable_feature = of_property_read_bool(dev->of_node,
                                                  "vendor,enable-feature");

    platform_set_drvdata(pdev, pdata);
    dev_info(dev, "Probe succeeded: reg=0x%x, irq=%d\n",
             pdata->reg_base, pdata->irq_num);
    return 0;
}

static int my_remove(struct platform_device *pdev) {
    dev_info(&pdev->dev, "Removing device\n");
    return 0;
}

static const struct of_device_id my_of_match[] = {
    { .compatible = "vendor,mydevice", },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, my_of_match);

static struct platform_driver my_platform_driver = {
    .probe  = my_probe,
    .remove = my_remove,
    .driver = {
        .name           = "my_platform_drv",
        .of_match_table = my_of_match,
    },
};

module_platform_driver(my_platform_driver);
MODULE_LICENSE("GPL");
```

#### 3. 设备树与驱动的绑定过程

```
设备树中定义节点（compatible = "vendor,mydevice"）
        ↓
内核启动时 unflatten_device_tree() 将 DTB 解析为 device_node 树
        ↓
platform_device_register() 为每个匹配的节点创建 platform_device
        ↓
总线匹配：platform_match → of_match_node → 查 compatible 表
        ↓
找到匹配 → 调用驱动的 .probe 函数
        ↓
驱动注册并开始管理硬件
```

| 主次设备号 | 无 | 驱动注册时需要主设备号和次设备号 |

## 调试技术

### 1. 串口控制台（Serial Console）

串口是嵌入式 Linux 开发中最基础、最重要的调试手段。通过 UART 将串口线连接到宿主机，可以使用终端软件与目标设备通信。



## GCC 编译与 Makefile

### GCC 编译流程

GCC 将源代码转换为可执行文件需要四个步骤：

```
源文件 (.c/.cpp)
    ↓ 1. 预处理 (cpp)
    ↓    展开 #include、#define，处理条件编译
预处理后的文件 (.i)
    ↓ 2. 编译 (cc1)
    ↓    将 C 代码转换为汇编语言
汇编文件 (.s)
    ↓ 3. 汇编 (as)
    ↓    将汇编代码转换为机器码（目标文件）
目标文件 (.o)
    ↓ 4. 链接 (ld)
    ↓    解析符号引用，生成可执行文件
可执行文件 (ELF)
```

### GCC 常用选项

```bash
# 基本选项
gcc -c hello.c               # 只编译为目标文件（.o）
gcc -S hello.c               # 只编译为汇编文件（.s）
gcc -E hello.c               # 只预处理
gcc -o hello hello.c         # 指定输出文件名

# 优化选项
gcc -O0 hello.c              # 不优化（默认，调试用）
gcc -O1 hello.c              # 轻度优化
gcc -O2 hello.c              # 较强调优（生产环境常用）
gcc -Os hello.c              # 优化体积
gcc -O3 hello.c              # 最高优化

# 调试选项
gcc -g hello.c               # 生成调试信息（GDB 调试必需）
gcc -ggdb hello.c            # 生成 GDB 增强的调试信息

# 警告选项
gcc -Wall -Wextra hello.c    # 启用常用警告
gcc -Werror hello.c          # 将所有警告视为错误
gcc -pedantic hello.c        # 严格遵循 ISO 标准

# 交叉编译
arm-linux-gnueabihf-gcc -march=armv7-a -mfpu=vfpv3 hello.c
```

### 嵌入式常用 Makefile

```makefile
# 交叉编译通用 Makefile
CROSS_COMPILE ?= arm-linux-gnueabihf-
CC  = $(CROSS_COMPILE)gcc
LD  = $(CROSS_COMPILE)ld
AR  = $(CROSS_COMPILE)ar
OBJCOPY = $(CROSS_COMPILE)objcopy
OBJDUMP = $(CROSS_COMPILE)objdump
SIZE    = $(CROSS_COMPILE)size

TARGET = my_app
SRCS   = main.c uart.c gpio.c
OBJS   = $(SRCS:.c=.o)

CFLAGS  = -O2 -g -Wall -Wextra -march=armv7-a
LDFLAGS = -lm -lpthread

.PHONY: all clean dist

all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) -o $@ $^ $(LDFLAGS)
	$(OBJCOPY) -O binary $@ $@.bin
	$(SIZE) $@

%.o: %.c
	$(CC) $(CFLAGS) -c -o $@ $<

clean:
	rm -f $(OBJS) $(TARGET) $(TARGET).bin

dist: $(TARGET)
	arm-linux-gnueabihf-strip $(TARGET)
	cp $(TARGET) /srv/nfs/rootfs/usr/bin/
```

## ARM 处理器模式

ARM 架构定义了以下 7 种处理器模式：

| 模式 | 缩写 | 用途 |
|------|------|------|
| 用户模式（User） | usr | 正常的程序执行模式，大多数应用程序在此模式运行 |
| 快速中断模式（FIQ） | fiq | 用于高速数据传输，有独立的寄存器组减少上下文切换开销 |
| 外部中断模式（IRQ） | irq | 通用中断处理，用于处理 GPIO、定时器等常规中断 |
| 管理模式（Supervisor） | svc | 操作系统保护模式，执行特权指令，系统调用从 usr 切换到 svc |
| 数据访问终止模式（Abort） | abt | 数据或指令预取终止时进入，用于虚拟内存和存储保护 |
| 系统模式（System） | sys | 运行操作系统任务的特权用户模式，可访问所有寄存器 |
| 未定义模式（Undefined） | und | 遇到未定义的指令时进入，用于协处理器软件仿真 |

模式切换通过 `CPSR`（当前程序状态寄存器）的模式位（M[4:0]）控制。异常事件（复位、中断、SWI 指令）会自动触发模式切换。

## 实战：从零构建嵌入式 Linux 系统

### 基于 QEMU + ARM 的最小系统构建流程

