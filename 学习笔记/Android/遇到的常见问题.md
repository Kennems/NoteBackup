# 遇到的常见问题

## StaggeredGridLayoutManager清空数据抛出异常

**问题概述**
 在使用 `StaggeredGridLayoutManager` 的 RecyclerView 中，下拉刷新或切换页面后清空/重置数据时，Android 会抛出：

```
IndexOutOfBoundsException: Index 0 out of bounds for length 0
```

------

**问题原因**
 `StaggeredGridLayoutManager` 默认的 **gap 修补（gap handling）** 机制会在布局或滚动状态变化后自动调用 `checkForGaps()`，并在内部尝试访问已被清空的数据缓存（span cache），导致对空列表下标 0 越界访问。

------

**解决方案**

1. **关闭 gap 修补**

   ```kotlin
   lm = StaggeredGridLayoutManager(spanCount, StaggeredGridLayoutManager.VERTICAL).apply {
       gapStrategy = StaggeredGridLayoutManager.GAP_HANDLING_NONE
   }
   recyclerView.layoutManager = lm
   ```

2. （可选的双保险）在 Adapter 的 `onBindViewHolder` 中加入位置检查，避免对空列表或越界索引进行访问：

   ```kotlin
   if (position in 0 until items.size) {
       holder.bind(items[position])
   }
   ```

3. 切换到其它布局管理器（如 `GridLayoutManager` 或 `LinearLayoutManager`）时，不会触发该 gap 修补逻辑。

## lambda引用和调用

在你的 `HomePage` 中调用 `ChatList` 时写成了：

```
0 -> ChatList(viewModel.chats) {
    onChatClick
}
```

而不是：

```
0 -> ChatList(viewModel.chats) { chat ->
    onChatClick(chat)
}
```

也就是说，你只是“传入了一个 lambda 引用”，但**没有真正调用**外层的回调函数 `onChatClick`。
 这会导致 `ChatList` 内部虽然触发了点击事件，但外层 `WeMainScreen` 的回调永远不会被调用。
