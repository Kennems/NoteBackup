# Prompt Engineering

## 概述

Prompt Engineering（提示工程）是指设计和优化输入提示（Prompt），以引导大语言模型（LLM）生成更准确、有用输出的实践。随着 LLM 能力不断增强，提示工程已成为与 AI 有效交互的核心技能。

## 核心技巧

### 1. Zero-shot（零样本提示）
直接给出任务指令，不提供示例。适用于简单、定义明确的任务。

```
请将以下句子翻译成英文："今天天气真好。"
```

### 2. Few-shot（少样本提示）
提供 2-5 个输入-输出示例，引导模型理解格式和风格。适合需要保持特定语气或格式一致性的任务。通常 3-5 个示例效果最佳，超过后收益递减。

```
将中文句子转为正式邮件语气：
输入："明天开会改到下午三点"
输出："尊敬的同事，原定会议已调整至明日15:00举行，请知悉。"
输入："报告还没写好，晚点交"
输出：
```

### 3. Chain-of-Thought（思维链）
要求模型分步推理后再给出答案，显著提升数学、逻辑和多步推理任务的准确率。最简单的用法是在 Prompt 末尾加上 "让我们一步步思考"（Let's think step by step）。

```
问题：一个商店买了 24 个苹果，卖掉了 1/3，然后又买了 12 个，现在有多少个？
让我们一步步思考：
```

### 4. Role Prompting（角色提示）
为模型指定一个专业角色（如 "你是资深网络安全工程师"），使其在特定领域内提供更专业的回答。

## CRAFT 框架

一个系统化的 Prompt 设计方法：

- **C**ontext（上下文）：提供背景、领域和约束条件
- **R**ole（角色）：指定 AI 扮演的身份
- **A**ction（动作）：明确需要执行的任务
- **F**ormat（格式）：规定输出结构（JSON、表格、Markdown 等）
- **T**one（语气）：指定沟通风格

## 进阶技巧

- **Self-Consistency**：多次运行 CoT 后投票选取最一致答案，用于高确定性场景
- **Prompt Chaining**：将复杂任务拆分为多个串行 Prompt，每步专注于一个子任务。生产环境 A/B 测试显示验证循环（generate → validate → correct）模式可减少约 73% 错误（dev.to / Alchemic Technology, 2025）
- **RAG**（检索增强生成）：将外部知识库检索结果注入 Prompt，有效减少幻觉
- **Tree of Thoughts**：让模型同时探索多条推理路径并评估，适合复杂规划任务

## 常见反模式

| 反模式 | 问题 | 改进方案 |
|--------|------|----------|
| 指令模糊（"改好一点"） | 缺乏明确标准 | 给出具体改进方向 |
| Prompt 过长（>500 字） | 稀释关键指令 | 精简上下文+清晰任务 |
| 未指定输出格式 | 输出不一致 | 明确要求 JSON/表格/列表 |
| "不要做 X" | 模型反而关注 X | 正向引导："请使用 Y 代替" |

## 实用建议

- **Prompt 要版本化管理**：像代码一样使用版本控制工具（如 promptfoo）管理 Prompt 变更
- **充分利用 Prompt Caching**：对固定系统提示使用缓存控制，可降低约 90% 成本（Anthropic 官方数据, 2024）
- **从简单开始**：先 Zero-shot → 效果不够加 Few-shot → 需推理加 CoT → 复杂任务用 Chaining/RAG
